# Rescore of existing quality runs with deterministic checks

`npm run test:quality:rescore -- ../bespoke-ai-vscode-ext/test-results` was run over every `test-results/quality-*` folder that has at least one `raw-response.txt` (48 runs; `quality-2026-03-01T22-33-34-api-ollama-qwen3-4b` has none and is left out). No model calls were made. The checks come from `src/test/quality/deterministic-checks.ts`, and each one targets a failure class from [`error-analysis-2026-03-sonnet.md`](error-analysis-2026-03-sonnet.md).

## What changed and why

1. Layer 1 now runs six deterministic checks on every scenario. It writes `checks.json` and a `rendered.txt` join (`…prefix⟦completion⟧suffix…`) for the judge, and adds per-check `{applied, failed}` counts and provenance (commit, dirty flag, rubric hash, and a `judge` field for Layer 2 to fill) to `summary.json`.
2. The checks were calibrated against the March analysis. On the 03-26 21:32 run, `boundary-ws` flags exactly the 21 scenarios the analyst marked as missing a leading space. `suffix-echo` flags only `prose-long-prefix-narrative`, and `journal-date` flags the three journal-structure cases. The `boundary-ws` failure counts for the 03-02 runs match the analysis's cross-run table: `01-43-42-claude-code-haiku` (33), `01-51-23-api-anthropic-haiku` (prefill, 5) and `01-43-41-api-xai-grok` (11). The denominators differ, though. The analysis counted prose completions at a word boundary. Here the denominator is every non-empty prose completion without the `mid_word` flag, and the end seam is checked as well.
3. **Combined pass** means that the judge passed the scenario and every applicable deterministic check passed. It is computed only over scenarios that have a parseable `validation.md`, so it can only be equal to or lower than the judge rate. For the 03-26 21:32 sonnet run it is 67.7% against 82.8% from the judge. Most of the gap is the missing-space defect, which the judge never catches.
4. Cells read `failed/applied`, and a check applies only where it is meaningful. `boundary-ws` runs on prose only, `suffix-echo` needs a raw response and a normalized suffix of at least 30 characters, and `journal-date` needs two or more `MM-DD-YY` headings in the context. `—` means the check never applied. `non-empty` counts provider errors and missing raw responses as failures, so rows with high counts (the Anthropic API runs, the Ollama runs) mostly reflect broken runs, not model quality.
5. Harness fixes: `list-marker-echo` now uses `must_not_start_with: ['- ']` instead of `must_not_include`. The stale "No suffix" note in `jnl-mid-paragraph` was rewritten as a tight-gap note. `mid_word` is set on `prose-mid-word`, `code-ts-partial-word`, `regression-prose-partial-word-newline-suffix` and `regression-prose-partial-date-not-continued`. `expect_empty_ok` is set on `code-full-py-pipeline-dispatch` and `prose-journal-jnl-mid-paragraph`. `max_completion_chars: 120` is set on `prose-full-api-versioning` only.

## Caveats

- **Historical runs have no provenance.** No run before this change recorded the judge model or the git commit. Judge pass rates come from whichever Claude session wrote the `validation.md` files, and different runs may have used different judges.
- Scenario flags (`mid_word`, caps, `expect_empty_ok`, `must_not_start_with`) are applied to old runs by looking up the scenario id in the current source. Older runs used earlier scenario sets, so the `applied` counts differ between runs.
- The checks run on the truncated prefix and suffix saved in `input.json`, which is what the model saw, not on the full scenario text.
- Judge verdicts are parsed from four historical `validation.md` formats, and none failed to parse. Judge rates are computed over judged scenarios only. The 03-26 20:54 run has 84 of 99 judged, and the 03-04 qwen35 run has 41 of 97.
- These checks each catch one narrow class of defect. A clean row does not mean the completions are good. Tight-gap collisions such as `looks way so much better` and distant-suffix completion still need the judge.
